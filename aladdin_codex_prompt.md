## Сначала

Прочитай существующие инструкции и проверь файлы. Сохрани пользовательские изменения. Если соответствующие документы уже существуют, проверь и поправь их; не генерируй проект заново.

Если документов нет, создай:
- AGENTS.md: краткие правила одной карточки.
- ROADMAP.md: Markdown checklist с ID T00–T20 и зависимостями.
- docs/TASKS.md: объём, критерии и проверка каждой карточки.
- docs/GAME_DESIGN.md: итоговый замысел из описания ниже, явно для нескольких PR.
- docs/ARCHITECTURE.md: короткие решения по стеку/данным/save, без реализации.
- docs/ACCEPTANCE.md: приёмка полного эпизода, относящаяся к T19.
- docs/PLAN.md: рабочий цикл через PR, без команды «сделать весь эпизод».
- docs/STATE.md: честное начальное состояние, краткий остаток и следующий ID.
- .github/pull_request_template.md: ID, изменение, проверки, roadmap и ограничения.
- README.md: запуск одной карточки и ссылки на roadmap/карточки.

Не вводи отдельные статусы в JSON, базу задач, dashboard или бота. ROADMAP.md является единственным checklist. Достаточно TODO, IN REVIEW, DONE и BLOCKED по правилам ниже.

## Правила для всех следующих запусков

В AGENTS.md зафиксируй:
1. Прочитать ROADMAP.md, короткий docs/STATE.md и только выбранную карточку. Остальные документы и код читать по необходимости.
2. Выполнять один явно выбранный ID. Если ID не указан, выбрать одну открытую карточку с готовыми зависимостями.
3. Если зависимость не готова, не выполнять её заодно. Если карточка слишком велика, разделить на дочерние ID, сохранив родителя открытым.
4. Обычные технические решения принимать самостоятельно в пределах карточки.
5. После текущей карточки остановиться. Никогда автоматически не переходить к следующей.
6. Не перечитывать весь проект, не переустанавливать готовые зависимости, не делать полный экспорт каждый раз. Субагентов по умолчанию не запускать.
7. Добавлять проверки существенных правил и необходимые регрессии; не тестировать каждую простую функцию.
8. Честно различать PASS, FAIL, NOT RUN, BLOCKED. Headless не подтверждает изображение и ощущение боя; экспорт Windows из Linux не подтверждает запуск на Windows.
9. В том же diff обновлять roadmap и короткое состояние. Предложенную галочку ставить только при выполнении/проверке обязательных критериев выбранной карточки.
10. Частичная работа и непроверенный обязательный пункт оставляют карточку открытой. Сохранять полезный результат и конкретный остаток.

## Галочка и PR

В основной ветке пустой checkbox означает TODO, отмеченный означает влитый DONE. В открытом PR предложенная галочка означает IN REVIEW. После merge код и галочка попадают в базовую ветку вместе. Закрытие без merge прогресс не меняет.

Название PR: «[T00] Правила проекта и roadmap». Если открыть PR инструментами нельзя, подготовь diff и текст описания для штатного создания PR пользователем. Не утверждай, что PR создан, если этого не было. Номер/URL неизвестного PR не выдумывай.

## Итоговый игровой замысел

Игра «Аладдин: Тени Аграбы»: один управляемый Аладдин, офлайн 2D action RPG, без партии. Godot 4.7.2 stable standard, typed GDScript, Compatibility. Вид сверху 3/4, свободное движение, четыре направления, SNES-подобная графика, 320×180, тайлы 16×16, nearest и целое увеличение. Русский интерфейс, кириллица.

Итог нескольких задач: квартал Аграбы с базаром, переулком, складом, двумя торговцами, скупщиком, тремя стражниками и одним бандитом. Бой с подготовкой/попаданием/восстановлением, ручная атака Space/ЛКМ, рывок Q без прохождения стен. Shift для скрытности. E взаимодействие, удержание F кража, I инвентарь, Esc пауза, F5/F9 save/load. GUI останавливает время и блокирует ввод в мир.

Стража видит сектор/дистанцию и учитывает стены: патруль, подозрение, преследование, последняя известная позиция, поиск, возврат. Она не знает скрытую текущую позицию. Кража переносит предмет один раз и сохраняет владельца/источник. Без реального свидетеля нет магической тревоги. Законный торговец отказывает в покупке краденого; скупщик принимает его дешевле. Сделки целостны, запасы/бюджеты конечны, отрицательные количества и бесконечная перепродажа запрещены.

Пять обычных товаров, еда и уникальная лампа. Квест: заказ скупщика, проникновение на склад, получение лампы, возврат и единственная награда. Ранняя находка лампы допустима, повторные диалоги/загрузка не дублируют награду. Лампу нельзя случайно продать. Поражение возвращает игрока на старт, лечит, снимает часть денег, сохраняет квестовый предмет.

Версионированный save хранит игрока, происхождение вещей, контейнеры, лампу/квест, запасы/деньги торговцев, время и необходимую тревогу. Загрузка не возвращает добычу. Запись безопасна; повреждённый файл не сбрасывает прогресс молча. День примерно шесть минут активной игры; пополнение один раз в день и ограниченная реакция цен на запас. Пауза и реальное время между запусками не двигают часы.

Цель продукта: эпизод примерно на 10–15 минут. Карманные кражи, крыши, Джинн, магия и другие районы появляются отдельным будущим объёмом. Сейчас их не реализовывать.

### T00: Правила проекта и roadmap

Зависимости: нет. Объём: Создать или проверить документы, карточки задач и шаблон PR. В этой карточке документация является конечным результатом.

Критерии: Есть ROADMAP.md, AGENTS.md, docs/TASKS.md, docs/STATE.md и шаблон PR. ID и зависимости согласованы; один запуск выполняет одну карточку. Все будущие задачи открыты; только T00 получает предложенную галочку.

Проверка: Проверить документы, ссылки и границы задач. Godot не нужен.

Вне объёма: Установка движка, игровой код, ассеты и CI.

### T01: Запускаемый Godot проект

Зависимости: T00. Объём: Создать project.godot и одну стартовую сцену, .gitignore и команды запуска/импорта. Проверить среду и подготовить bootstrap только при отсутствии движка.

Критерии: Стартовая сцена запускается указанной стабильной версией Godot. Настроены Compatibility, 320×180, nearest filtering и целое увеличение. README содержит воспроизводимый запуск; импорт выявляет ошибки.

Проверка: Фактический импорт и короткий запуск. Без движка карточка BLOCKED и остаётся открытой.

Вне объёма: Движение, большая карта, меню и экспорт.

### T02: Движение Аладдина

Зависимости: T01. Объём: Добавить движение и столкновения на маленькой площадке с несколькими стенами. Минимальный пиксельный спрайт показывает направление.

Критерии: WASD/стрелки работают; диагональ не быстрее прямого движения. Персонаж не проходит сквозь стены и хранит направление взгляда. Есть четыре направления idle/walk и согласованное положение ног.

Проверка: Перемещение и столкновения; статус визуальной проверки указать отдельно.

Вне объёма: Бой, рывок, стелс, NPC и окончательная графика.

### T03: Планировка базара

Зависимости: T02. Объём: Собрать квартал: базар, склад, переулок, место скупщика и площадка боя. NPC пока могут быть статичными маркерами ролей.

Критерии: Зоны связаны доступными маршрутами и корректными столкновениями. Есть путь к складу через переулок и прямой путь. Положение ног и сортировка по Y не ломают изображение.

Проверка: Маршруты, стены и запуск карты.

Вне объёма: Патрули, квест, новые районы и сложное декорирование.

### T04: Меню, HUD и пауза

Зависимости: T02. Объём: Добавить русское меню, HUD здоровья/денег и паузу. Продолжить явно недоступно до реализации save.

Критерии: Новая игра открывает существующую сцену; Esc ставит игру на паузу. HUD получает данные из единого состояния игрока. Кириллица поддерживается; ввод меню не управляет миром.

Проверка: Переходы, пауза и ввод; фактическую проверку читаемости указать отдельно.

Вне объёма: Сохранения, инвентарь, торговое окно и большие настройки.

### T05: Взаимодействие с объектами

Зависимости: T03, T04. Объём: Сделать выбор ближайшей подходящей цели, подсказку и действие E. Подключить простой диалог NPC и контейнер.

Критерии: При нескольких целях выбор стабилен и соответствует подсказке. За пределами дистанции и в меню действие не выполняется. NPC и контейнер используют общий механизм взаимодействия.

Проверка: Две близкие цели, отход от цели и попытка действия в паузе.

Вне объёма: Кража, передача предметов и полноценный квест.

### T06: Предметы и инвентарь

Зависимости: T05. Объём: Добавить товары, еду и лампу в данные, экземпляры/стеки и окно I. Происхождение предметов предусмотреть сразу.

Критерии: Добавление/удаление не дублирует предметы и не создаёт отрицательные количества. Честные и краденые предметы сохраняют разные происхождения. Лампа уникальна и защищена как квестовая; еда лечит; I останавливает мир.

Проверка: Количество, разные источники одного товара, уникальность и применение еды.

Вне объёма: Магазины, кражи, сохранение мира и экипировка.

### T07: Честная торговля

Зависимости: T06. Объём: Подключить двух торговцев с запасами/бюджетами, торговое окно и целостные покупки/продажи.

Критерии: Сделка меняет деньги и товары обеих сторон целиком либо не меняет ничего. Есть отказы при нехватке денег/товара; законный торговец не покупает краденое. Лампа не продаётся; немедленная перепродажа одному NPC не приносит прибыль.

Проверка: Успешные сделки и отказы без частичного изменения состояния.

Вне объёма: Пополнение дня, реакция цен и особые условия скупщика.

### T08: Удар и уклонение игрока

Зависимости: T03, T04. Объём: Добавить ручную атаку и рывок Q. Для проверки достаточно манекена без AI.

Критерии: Удар направлен по взгляду и имеет окно попадания/восстановление. Один взмах наносит одной цели урон один раз; стена мешает удару. Рывок имеет cooldown, не проходит стены; GUI блокирует боевой ввод.

Проверка: Повторные кадры overlap, cooldown и преграда; читаемость рендера отдельно.

Вне объёма: AI врагов, комбо и магия.

### T09: Бандит и восстановление после поражения

Зависимости: T08. Объём: Добавить одного врага с подготовкой удара и возвращение игрока к старту после поражения.

Критерии: Игрок может увидеть атаку бандита, уклониться и победить. Урон меняет здоровье и даёт обратную связь. Поражение лечит, снимает небольшую долю денег и сохраняет квестовые предметы.

Проверка: Дуэль и восстановление; headless проверка не подтверждает ощущение боя.

Вне объёма: Толпы, патрули и сложная тактика.

### T10: Патруль и видимость стражи

Зависимости: T03. Объём: Добавить трёх стражников, патрули и общую проверку дистанции, сектора и преграды.

Критерии: Стражники проходят маршруты без застревания в препятствиях. В секторе без стены цель видна; за стеной не видна. Параметры видимости пригодны для последующего поиска свидетелей.

Проверка: Одинаковая дистанция со стеной и без неё; маршруты патруля.

Вне объёма: Полная тревога, преступления и кражи.

### T11: Подозрение, преследование и поиск

Зависимости: T10, T04. Объём: Добавить состояния стражи, Shift для скрытного движения и индикатор обнаружения.

Критерии: Работают подозрение, преследование, последняя известная позиция, поиск и возврат. После потери обзора стража не знает скрытую текущую позицию игрока. Тревога прекращается после ухода; Shift снижает скорость и применимый шум.

Проверка: Переходы состояний, стена и потеря цели.

Вне объёма: Преступления, сложная акустика и карманные кражи.

### T12: Кража из контейнера

Зависимости: T05, T06. Объём: Добавить удержание F, отмену и перенос чужого товара с происхождением. Последствия для свидетелей добавятся отдельной карточкой.

Критерии: Успех переносит предмет один раз и очищает источник. Отмена/отход ничего не передают. Владелец и отметка кражи сохраняются; пустой контейнер не создаёт добычу.

Проверка: Успех, отмена, повторное действие и происхождение.

Вне объёма: Свидетели, тревога и карманные кражи.

### T13: Свидетели преступления и скупщик

Зависимости: T07, T11, T12. Объём: Связать кражу с действительными свидетелями и тревогой; дать скупщику покупку обычного краденого со скидкой.

Критерии: Замеченная кража вызывает реакцию; без видимости нет магической тревоги. Свидетель передаёт известное место, а не скрытую постоянно обновляемую позицию. Скупщик покупает краденое дешевле; законный торговец отказывает; сделка целостна.

Проверка: Кража со свидетелем, за стеной и без свидетеля; продажа обоим типам NPC.

Вне объёма: Репутация города, длительный розыск и отмывание.

### T14: Заказ на лампу

Зависимости: T05, T13. Объём: Добавить стадии заказа, лампу на складе, передачу скупщику, финал и единственную награду.

Критерии: Квест проходит скрытно или с тревогой; финал доступен после передачи. Лампа до принятия заказа корректно учитывается. Лампа существует максимум в одном месте; повторный диалог не повторяет награду.

Проверка: Обычный порядок, ранняя лампа, повторное завершение и маршрут.

Вне объёма: Джинн, новые задания и полное сохранение мира.

### T15: Основа сохранения игрока

Зависимости: T06. Объём: Сделать versioned save игрока: положение, здоровье, деньги, инвентарь/происхождение. Безопасная запись и обработка повреждения.

Критерии: Данные игрока восстанавливаются без потери происхождения/количества. Ошибка записи сохраняет прежний корректный save; повреждение не вызывает молчаливый сброс. F5/F9 и Продолжить поддерживают этот объём; ограничения мира явно названы.

Проверка: Round-trip игрока, повреждённый файл и изолированный путь тестов.

Вне объёма: Полный save квеста, контейнеров, торговли и тревоги.

### T16: Сохранение состояния квартала

Зависимости: T14, T15. Объём: Расширить существующий save стабильными ID мира, контейнерами, лампой, квестом, торговцами и состоянием тревоги.

Критерии: Загрузка не возвращает добычу, не создаёт лампу и не повторяет награду. Запасы/бюджеты торговцев и квест восстанавливаются. Активная тревога не исчезает как способ обхода; save игрока продолжает работать.

Проверка: Загрузка после кражи/покупки/заказа и повторная загрузка после финала.

Вне объёма: Универсальные миграции, cloud saves и каждый кадр анимации.

### T17: Игровой день и простая экономика

Зависимости: T07, T16. Объём: Добавить шестиминутный день, пополнение один раз в день и ограниченную реакцию цены на остаток. Сохранить время/факт пополнения.

Критерии: Пауза не двигает время; между запусками реальное время не учитывается. Пополнение выполняется один раз, в том числе после загрузки. Цены/запасы допустимы; реакция цены не создаёт бесконечную перепродажу.

Проверка: Граница дня, повторный update, загрузка и цикл покупки/продажи.

Вне объёма: Караваны, производство и спрос каждого жителя.

### T18: Согласованная пиксельная графика

Зависимости: T03, T04, T09, T11, T13. Объём: Довести существующие тайлы, персонажей и UI до единого небольшого SNES-подобного комплекта.

Критерии: Роли NPC, важные объекты, направления и состояния различимы. Палитра, размер, положение ног, масштаб и кириллица согласованы. Происхождение сторонних ассетов указано; приложены генераторы, если использовались.

Проверка: Настоящий рендер и визуальный отчёт. Без renderer визуальная приёмка не закрыта, checkbox остаётся пустым.

Вне объёма: Новые механики, большой контент и многочисленные итерации генерации.

### T19: Проверка полного эпизода

Зависимости: T14, T16, T17, T18, T20. Объём: Проверить цикл по docs/ACCEPTANCE.md и исправить ограниченные ошибки интеграции.

Критерии: Квест, бой, кража, преследование, сбыт, покупка и загрузка связаны в игру. Проверки существенных правил проходят; непроверенные ручные пункты названы. При большом объёме проблем созданы отдельные карточки, а T19 остаётся открытой.

Проверка: Сквозной сценарий и необходимые регрессии. Для приёмки визуальных пунктов нужен реальный просмотр; при его отсутствии карточка не закрывается.

Вне объёма: Новые способности/районы и переписывание всех систем.

### T20: Сборки для продуктового ревью

Зависимости: T14, T16, T17. Объём: Подготовить экспорт, доступные Linux/Windows x86_64 пакеты, материалы ревью и инструкции запуска.

Критерии: Совместимые export templates используются, экспорт проходит. Есть игровой пакет и README с управлением/запуском. Отдельно названы экспортированная платформа, фактический запуск и ограничения.

Проверка: Экспорт и доступный запуск. Экспорт Windows из Linux не является запуском на Windows; без templates карточка BLOCKED.

Вне объёма: Web публикация, магазин, установщик и следующий большой этап.


## Критерии завершения текущего T00

- Нужные документы и шаблон PR существуют; ID, зависимости и ссылки согласованы.
- Везде ясно, что один запуск выполняет одну карточку. Полный замысел не является заданием текущего запуска.
- T00 получает предложенную галочку в текущем diff; T01–T20 остаются открытыми.
- docs/STATE.md честно сообщает, что игровой реализации пока нет, если репозиторий пустой.
- README содержит короткий промпт вида «Выполни только T02 из docs/TASKS.md; проверь критерии, обнови roadmap в том же PR, затем остановись».
- Проверка не требует установки движка. Игровой код, ассеты и CI не создаются.

В конце сообщи результат T00, что проверено и что рекомендовано следующим. Затем остановись. T01 в этом запуске не начинай.
