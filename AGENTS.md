# Правила проекта

«Аладдин: Тени Аграбы»: Godot 2D action RPG, один герой, офлайн, SNES-подобные пиксели, русский интерфейс. Подробный итоговый замысел находится в docs/GAME_DESIGN.md.

## Один запуск, одна карточка

1. Прочитай ROADMAP.md, короткий docs/STATE.md и только выбранную карточку docs/TASKS.md. Другие документы и код читай по необходимости для этой карточки.
2. Выполни только ID из запроса. Если ID не указан, выбери одну незавершённую карточку с выполненными зависимостями и назови её перед работой.
3. Итоговый игровой эпизод является целью нескольких PR. Не делай весь M0/M1 за один запуск и не переходи к следующей карточке после завершения текущей.
4. Обычные технические детали выбирай самостоятельно. Существенные решения и блокеры запиши в docs/STATE.md.
5. T00 завершается документами. Для карточек реализации документация сопровождает конкретный работающий результат.
6. Если зависимость не готова, не выполняй её вместе с выбранной карточкой. Укажи блокер. Если сама карточка оказалась большой, раздели её на проверяемые дочерние карточки и остановись на согласованном текущем объёме.
7. Не запускай субагентов по умолчанию: отдельное разрешение на параллельную работу должно быть в текущем запросе.

## Контекст и объём

- Не перечитывай весь репозиторий и все дизайн-документы в каждом запуске. Поиск и чтение должны отвечать вопросу текущей карточки.
- Сначала используй уже имеющиеся движок, ассеты, команды и решения. Не переустанавливай Godot и templates без необходимости.
- Не создавай универсальный движок, framework, backend, telemetry, multiplayer и платные зависимости.
- Не делай полный экспорт и генерацию большого набора графики в каждом PR. Для этого есть отдельные карточки.
- Не расширяй объём ради улучшений, не необходимых для текущих критериев.
- Сохраняй существующие файлы и изменения пользователя. Не сбрасывай git и не переписывай работающие системы без причины.

## Код и проверки

- Godot 4.7.2 stable standard, typed GDScript, Compatibility. При объективной недоступности версии следуй docs/ARCHITECTURE.md и зафиксируй фактическую стабильную 4.x.
- Единые правила предметов, денег, преступлений и квестов. Данные отделены от GUI; стабильные ID вместо Runtime Instance ID.
- Сделки/кражи/награды целостны. Происхождение краденого сохраняется при операциях и загрузке.
- Маленькие изменения держат проект запускаемым. Проверяй текущие критерии и затронутые регрессии.
- Добавляй осмысленные проверки существенных правил. Не пиши тест на каждый простой метод и не создавай тестовую инфраструктуру ради правки документа.
- Проверки различают PASS, FAIL, NOT RUN, BLOCKED. Ошибки/таймаут дают ненулевой код.
- Headless не подтверждает изображение и ощущение боя. Скриншоты берутся из настоящего проекта. Экспорт Windows не равен запуску на Windows.

## Roadmap и PR

- В том же diff, где реализована карточка, обнови ROADMAP.md и docs/STATE.md.
- Поставь предложенную галочку только у текущего ID и только если обязательные критерии карточки выполнены и проверены. FAIL, BLOCKED и непроверенный обязательный пункт оставляют checkbox пустым.
- В основной ветке [x] означает влитую завершённую карточку. В PR это предложение, которое становится принятым после merge. Закрытый без merge PR прогресс не меняет.
- Частичный PR может сохранять полезную работу, но не закрывает карточку. Назови остаток и блокер. Родитель большой разделённой карточки остаётся открытым до выполнения всех частей.
- Используй заголовок PR вида «[T02] Движение Аладдина» и шаблон .github/pull_request_template.md. PR номер/URL записывай только если он реально известен; иначе достаточно ID.
- Если инструмента открытия PR нет, подготовь diff и описание для штатного создания PR пользователем. Не заявляй о созданном PR.
- Оставь краткий отчёт: ID, результат, проверки, ограничения, следующая подходящая карточка. Затем остановись.
