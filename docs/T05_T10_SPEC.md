# ТЗ текущего запуска: T05–T10

Основание: явный запрос пользователя на общий PR T05–T10 и шесть
субагентов `gpt-6.1-sol`, reasoning `medium`. Это разовое разрешение на пакет
карточек вместо обычного правила «один запуск, одна карточка». CODEX_START.md
описывает исторический T00; текущий запрос задаёт актуальный объём.

База: main, `70a5cda`, T00–T05 уже влиты (T05 — PR #6).
Источники требований: соответствующие карточки TASKS.md, ARCHITECTURE.md
и разделы управления, боя, предметов и торговли GAME_DESIGN.md.

## Границы и зависимости

- T05: проверить существующее взаимодействие и регрессии; не переделывать
  работающий механизм без найденного дефекта.
- T06: каталог пяти товаров, еды и лампы; стеки с происхождением,
  защита уникальной квестовой лампы, лечение едой, окно I с паузой.
- T07: два законных торговца с отдельными запасами/бюджетами, торговое окно,
  целостные покупки/продажи. Приёмка после готовности T06.
- T08: Space/ЛКМ — направленный удар с фазами и однократным попаданием;
  Q — рывок с cooldown и коллизиями; блокировка ввода через GUI.
- T09: один бандит с читаемой подготовкой удара, обратная связь урона,
  победа и восстановление у старта с потерей 10% денег. Приёмка после T08.
- T10: три стражника с маршрутами; общий запрос видимости по дистанции,
  сектору и стенам с настраиваемыми параметрами.

T11 и далее не реализуются. Нет тревоги/преследования, кражи, квестового
сценария, сохранений, смены дня, экспорта и окончательной графики T18.
Существующий пустой сундук и диалог скупщика сохраняются.

## Разделение работ

Каждый субагент работает в отдельном `work/agents/tXX` и ветке `agent/tXX`,
пишет код только своего блока, делает отдельный commit и передаёт основной
сессии SHA, список файлов, команды, результаты и ограничения. Не пушит,
не открывает PR, не меняет общие ROADMAP/STATE/README и чужой код.

- T05: существующий тест взаимодействия и дополнительный аудит его критериев.
- T06: `data/items.json`, каталог/инвентарь, InventoryUI, тест T06.
- T07: данные торговцев, TradeService/TradeUI, тест T07.
- T08: `scripts/player.gd`, компоненты боя/манекена, тест T08.
- T09: компонент бандита/восстановления, тест T09.
- T10: компоненты патруля/видимости, тест T10.

Основная сессия владеет общей связкой в game.gd, InputMap, стартовой сценой,
командами проверок, документацией и материалами ревью. После принятия блоков
она выполняет интеграцию и проверку итогового состояния.

## Контракты интеграции

Инвентарь — отдельные данные, без зависимости от GUI. Стек содержит стабильные
`stack_id`, `item_id`, `quantity`, `stolen`, `owner_id`, `source_id`,
`instance_id`. Разные происхождения не объединяются. Каталог хранит названия,
описания, целые цены, тип, флаги продажи/использования и иконку. Лампа имеет
постоянный ID экземпляра и не удаляется обычной операцией/продажей/едой.

`ItemInventory`: сигнал `changed`, `get_stacks()`, `get_stack(stack_id)`,
`count_item(item_id)`, `can_add_item(item_id, quantity, provenance)`,
`add_item(item_id, quantity, provenance)`,
`remove_item(stack_id, quantity, allow_quest=false)`,
`use_food(stack_id, player_state)`. Запросы возвращают копии данных.
Предусловия и неуспех возвращают false и не меняют состояние.

Торговля использует этот API, сохраняет происхождение, проверяет обе стороны
до изменения. Нельзя выдавать положительный результат при частичном изменении.
Точные сигнатуры TradeService/GUI согласуются между T06/T07 и основной сессией
до интеграции. Начальная игра получает небольшой законный набор и 30 динаров;
лампа и краденые экземпляры выдаются только тестовыми фикстурами.

Player остаётся владельцем движения. T08 добавляет
`receive_damage(amount: int, origin: Vector2 = Vector2.ZERO) -> bool`,
сигнал `defeated` и `reset_combat()`, использует существующий PlayerState.
T09 подписывается на поражение, возвращает игрока к сохранённому старту,
восстанавливает здоровье и уменьшает деньги, не трогая инвентарь.
Боевой блок ищет цели в группе `damageable` с методом `receive_damage`.
Общие меню при возврате подавляют удержанные движение, E, удар и Q.

T09/T10 предоставляют компактную функцию установки в существующий world;
заменяются только соответствующие статичные маркеры. Стража не атакует,
не создаёт тревогу и не получает знания о скрытой позиции.

## Приёмка основной сессией

1. Проверить diff каждого блока, соблюдение границ, ID и зависимостей.
2. Импорт/старт настоящего Godot 4.7.2 stable standard, Compatibility.
3. Прогнать T02–T05 и новые тесты T06–T10 с timeout/ненулевым кодом ошибки.
4. Проверить количества/происхождение/уникальность/еду; успешные и отказные
   сделки без частичных изменений, запрет краденого и лампы, отсутствие прибыли.
5. Проверить направление, фазы/overlap/стены/cooldown, GUI и удержанный ввод;
   дуэль, уклонение, урон и восстановление с сохранением квестового предмета.
6. Проверить три маршрута в настоящем квартале и одинаковую дистанцию
   видимости со стеной/без стены, сектор и переиспользование параметров.
7. Отдельно запустить настоящий рендер и просмотреть инвентарь, торговлю,
   удар/рывок, подготовку и попадание бандита, патруль. Headless не доказывает
   изображение или субъективное ощущение боя; последнее честно указать NOT RUN.
8. Проверить документацию/ссылки/шаблон PR, обновить ROADMAP и краткий STATE
   по фактически подтверждённым результатам. Только выполненные критерии
   позволяют предложить галочку. Открыть один общий PR и остановиться.
