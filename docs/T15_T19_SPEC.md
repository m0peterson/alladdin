# ТЗ T15–T19

Актуализировано 2026-11-01. База `89ad5d5` — merge PR #8, T00–T14.
Пользователь явно разрешил пакет и субагентов GPT‑6.1 Sol, reasoning medium.
Это исключение из обычного правила одной карточки за запуск. CODEX_START.md
содержит исторический запрос T00; текущий запрос задаёт T15–T19.
После пересоздания среды локальные результаты восстанавливаются; доказательства
проверок должны быть получены заново, общий результат сохраняется в origin.

## Приёмка и границы

| Блок | Результат и обязательная проверка |
| --- | --- |
| T15 | Versioned JSON игрока: положение, здоровье, динары, стеки/происхождение/стабильные ID. Строгая валидация до применения, temp+verify+replace, резервная копия и явная ошибка повреждения. F5/F9/Продолжить; round-trip, повреждение, отказ записи, backup, отдельный путь тестов. |
| T16 | WorldSave расширяет безопасный IO T15: контейнеры, единственная лампа, квест/награда, торговцы, тревога/последнее известное место и бандит. Полная валидация до мутаций и сигналов. Загрузка после кражи/покупки/заказа/финала, повторная загрузка без добычи/награды, сохранение тревоги. |
| T17 | GameClock: 360 секунд активной игры, пауза останавливает, офлайн время не учитывается. Одно пополнение каждого торговца за день, время и marker сохраняются атомарно. Ограниченная реакция цены без прибыльного цикла. Граница дня, повторный update, загрузка, пауза, отрицательные сценарии и overflow. |
| T18 | Компактный единый SNES-подобный комплект: различимые роли, объекты, направления и состояния, палитра/ноги/масштаб/кириллица. Собственные генераторы и готовые ассеты, attribution. Настоящий рендер, просмотр кадров и отчёт; headless изображение не подтверждает. |
| T19 | Сквозная проверка доступного эпизода и новых F5/F9/Continue/дня. Матрица ACCEPTANCE: PASS/FAIL/NOT RUN/BLOCKED, логи, ограниченные исправления интеграции. Остаётся BLOCKED до T20. |

T15 и T18 доступны от базы; T16 принимается после T15, T17 после T16,
подготовка самостоятельных модулей параллельная. T20 не входит в запрос:
экспорт и сборки не выполняются, T19 остаётся открытой. Галочка предлагается
только после проверки всех обязательных критериев конкретного ID.

## Владение файлами и контракты

Каждый исполнитель работает в отдельном git worktree, пишет только свой блок
и возвращает commit, команды, результаты и ограничения. Общие ROADMAP.md,
docs/STATE.md, README, tools/test.sh, интеграцию и PR ведёт root.

- T15: PlayerSave, ItemInventory snapshots/лимиты, game/menu/input и тест T15.
  Формат v1 `{version:1,scope:player,player:{position:{x,y},health,money,inventory:{stacks,next_stack_id}}}`.
  API: capture(position,state,inventory), validate(data)->String,
  read_file()->{ok,data|error}, write(data)->String, has_backup(), restore_backup().
- T16: WorldSave extends PlayerSave; v2 scope world, player сохраняется целиком.
  capture_world(game), validate(data), apply(data,game)->String. Snapshot API
  контейнеров/квеста/стражи/бандита; торговцев меняет только T17.
- T17: TradeService save_snapshot/validate_snapshot/restore_snapshot и
  refill_for_day(day,emit_change); GameClock setup(trades), advance(delta),
  save_snapshot/validate_snapshot/restore_snapshot, day_index/seconds_in_day.
  Clock сам выполняет refill до уведомлений, marker равен day_index.
- T18: собственные визуальные ресурсы/helpers/генераторы, только visual hunks
  guard/bandit, отчёт и небольшие настоящие PNG; game/menu не меняет.
- T19: tests/check_t15_t19.gd, отчёт/логи; игровые баги передаёт root.

Валидное состояние должно оставаться сохраняемым после разрешённых операций:
проверять предел stack ID и MAX_STACKS до создания стека, разрешать слияние
существующего. Невалидная поздняя секция мира не меняет даже игрока;
повторный apply из callback занятой операции отклоняется до мутаций.

Отдельный read-only аудит проверяет границы недоверенного JSON, целостность,
лимиты, инструменты и зависимости. Критические выводы требуют воспроизведения;
игра офлайн, редактирование собственного save не равно удалённой атаке.
Существующий `.github/pull_request_template.md` проверяется и используется.
