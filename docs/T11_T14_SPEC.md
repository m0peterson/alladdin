# ТЗ текущего запуска: T11–T14

Основание — явный запрос пользователя: четыре субагента `gpt-6.1-sol`,
reasoning `medium`, отдельный код каждого блока и один общий PR после приёмки.
Это разовое разрешение на пакет вместо правила одной карточки. CODEX_START.md
прочитан: он описывает исторический T00; актуальный объём задаёт текущий запрос.

База — main `3db379e`, T00–T10 влиты, включая PR #7.
Источники: AGENTS.md, карточки T11–T14 в TASKS.md, применимые разделы
GAME_DESIGN.md и ARCHITECTURE.md. Существующий PR template подходит пакету.

## Объём и порядок приёмки

- T11: подозрение, преследование, последнее известное место, ограниченный
  поиск, возврат на патруль; видимый индикатор. Shift замедляет движение
  и уменьшает применимый шум. Стена прекращает обновление знаний о цели.
- T12: удержание F с прогрессом и отменой; атомарный перенос чужих вещей
  из контейнера с сохранением stolen/owner_id/source_id/instance_id.
  Пустой источник и повторный ввод не создают добычу.
- T13: действительные свидетели (стража и ближайший владелец) по общей
  проверке видимости; сообщение стражнику содержит снимок места преступления.
  Скупщик покупает обычное краденое дешевле законной цены; законный торговец
  отказывает. Деньги, оба запаса и происхождение меняются целостно.
- T14: явное принятие заказа, уникальная лампа на складе, получение до/после
  принятия, передача скупщику, финальный диалог и одна награда. Два маршрута,
  скрытный и с тревогой, остаются проходимыми.

T11/T12 независимы на готовой базе. T13 принимается после них; T14 — после T13.
Внутренние зависимости разрешённого пакета интегрируются в этом порядке.
T15 и далее не начинаются: нет сохранений, смены дня, новых заданий,
генерации окончательной графики, export templates или сборок.

## Владение файлами

Каждый агент работает в отдельном git worktree `work/agents/tXX` и ветке
`agent/tXX`, коммитит только свой блок и передаёт SHA, список файлов,
команды проверок, результаты и ограничения. Не пушит и не открывает PR.
Общие документы и интеграционные файлы меняет только основная сессия.

- T11: guard_patrol.gd, player.gd, новый guard_detection_ui.gd, тест T11.
- T12: новые theft_target.gd, theft_controller.gd, theft_ui.gd, тест T12.
- T13: новые crime_service.gd / crime_witness.gd, trade_service.gd,
  trade_ui.gd, data/merchants.json, тест T13.
- T14: новые lamp_quest.gd и fence_ui.gd, тест T14.
- Основная сессия: game.gd, InputMap, сцены, установка контейнеров/свидетелей,
  общая интеграционная проверка и реальный рендер, README, ROADMAP, STATE,
  материалы приёмки и PR. Чужие блоки правит только по итогам ревью.

## Контракты

Существующие ItemInventory, ItemCatalog и PlayerState остаются источниками
предметов и денег; стабильный экземпляр лампы — ItemCatalog.LAMP_INSTANCE_ID.
GUI вызывает операции сервисов и не дописывает деньги/предметы самостоятельно.
Все новые сигнатуры агенты сообщают основной сессии до итоговой интеграции.

T11 сохраняет GuardPatrol.install(world), can_see() и патрульные счётчики.
Добавляет configure(player) и report_crime(position): последнее принимает
снимок координат, не ссылку на скрытую цель. Без configure патруль работает
как раньше. Индикатор получает список стражников; в модальных окнах ввод
подавляется до отпускания. Shift использует action `sneak`.

T12: TheftTarget наследует InteractionTarget, хранит конечный запас и владельца.
TheftController получает player, inventory и общий InteractionController,
работает с показанной целью и action `steal`. После полного атомарного успеха
выдаёт `theft_completed(event: Dictionary)` с полями source_id, owner_id,
position (место игрока в момент успеха), item_id, quantity. Событие не содержит
живую ссылку на игрока для постоянного слежения. Отпускание, отход, GUI,
удаление цели и невозможность приёма отменяют перенос.

T13 обрабатывает это событие, определяет свидетелей текущей геометрией
VisibilityQuery и передаёт стражникам только известную позицию. Скупщик
имеет отдельный конечный бюджет и запас; лампа исключена из обычной торговли.
Сигнатуры существующей торговли сохраняются; GUI показывает действительные
условия продажи и причину отказа законного торговца.

T14 получает общий inventory и PlayerState. Явные стадии и одна операция
передачи проверяют наличие единственной лампы и возможность награды до
изменения данных. Полученная раньше лампа учитывается при принятии.
FenceUI предлагает принять заказ / передать лампу / открыть скупку;
финал доступен после передачи. Новая игра создаёт все данные заново.
