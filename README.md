# Аладдин: Тени Аграбы

2D-проект Godot с небольшой площадкой для проверки движения Аладдина и требованиями для дальнейшей разработки игры небольшими задачами Codex.

Прогресс: [ROADMAP.md](ROADMAP.md). Объём одной задачи: [docs/TASKS.md](docs/TASKS.md). Текущее состояние: [docs/STATE.md](docs/STATE.md).

## Запуск и проверка проекта

Используется **Godot 4.7.2 stable standard**, без .NET. Стартовая сцена работает
с Compatibility renderer, viewport 320×180, nearest filtering и целочисленным
масштабированием. Начальный размер окна — 960×540.

В корне репозитория на Linux x86_64:

```sh
./tools/bootstrap-godot.sh
./tools/godot.sh
```

Bootstrap переиспользует подходящий движок либо скачивает
[официальную стандартную сборку 4.7.2](https://github.com/godotengine/godot-builds/releases/tag/4.7.2-stable)
в `.tools/godot/4.7.2/` и проверяет SHA-256 из метаданных релиза. Для скачивания
нужны Bash, curl, unzip и sha256sum. Godot 4.6.3, имеющийся в облачном окружении,
для этого проекта не используется. Явный путь к подходящему движку можно задать
через необязательный `GODOT_BIN`.

Открыть редактор: `./tools/godot.sh --editor`. На других платформах установите
Godot 4.7.2 standard, откройте `project.godot` в редакторе и нажмите F5.
Для графического запуска нужен доступный дисплей и OpenGL 3.3; игра не требует
внешних сервисов, API-ключей или Python.

```sh
./tools/check.sh
./tools/test.sh
```

Проверка требует Bash и GNU timeout: она импортирует проект, выполняет короткий
headless-запуск и проверяет готовность стартовой сцены и настройки viewport,
масштабирования и фильтрации. Каждому этапу отведено 60 секунд. Ошибки Godot,
ошибки скриптов и таймаут дают ненулевой код. Логи проверки находятся
в `.godot/check-logs/`; локальные настройки, кеши и данные — в `.godot/`.
Команды сами определяют каталог проекта и работают при вызове из другого каталога.

`tools/test.sh` запускает сценарий T02 через настоящий InputMap и физику:
WASD и стрелки, остановка, сохранение взгляда, одинаковая скорость по прямой
и диагонали, стороны трёх стен, скольжение, углы и четыре границы площадки.
Также проверяются idle/walk в четырёх направлениях и общая линия стоп.
Лимит — 60 секунд; ошибки и незавершённый сценарий дают ненулевой код.
Лог: `.godot/check-logs/movement.log`. Сначала выполните импорт через `check.sh`.

## Движение: T02

После запуска сразу открывается площадка с тремя стенами. Двигайтесь **WASD
или стрелками**. Скорость — 72 пикселя в секунду; диагональ нормализована.
При остановке герой сохраняет направление взгляда. На диагонали вертикаль
определяет взгляд. Столкновения происходят у ног; при упоре в стену герой
останавливается, при движении под углом скользит вдоль неё.

Временный спрайт 16×24 имеет idle и ходьбу в четырёх направлениях.
Происхождение и сетка: [assets/ATTRIBUTION.md](assets/ATTRIBUTION.md).
Базар и игровые системы относятся к следующим карточкам.

Проверены импорт, headless-сценарии и реальный графический запуск через Xorg
с Mesa llvmpipe. Отдельно просмотрены 22 кадра: площадка, четыре цикла ходьбы,
четыре idle и северная граница без пересечения с заголовком. Подсказка читается,
фильтрация пиксельная, линия стоп согласована. Материалы и команда повторения:
[artifacts/t02/README.md](artifacts/t02/README.md). Headless сам по себе
не подтверждает изображение. Ощущение управления остаётся для ревью пользователем.
Предупреждение о недоступном V-Sync относится к виртуальному дисплею.
Экспортные шаблоны и сборки относятся к T20.

## Как начать

Вариант с готовыми документами: распаковать пакет в выбранный репозиторий, сохранив существующие применимые инструкции. Передать Codex только текст CODEX_START.md. Это T00, проверка рабочего процесса.

Вариант без загрузки документов: вставить полный текст aladdin_codex_prompt.md в первую задачу с репозиторием. Он создаёт правила и roadmap, но не поручает реализацию игры в том же запуске. Следующим задачам достаточно короткого промпта из CODEX_NEXT_TASKS.md. Расширенные дизайн-документы в этом архиве полезны для точной реализации.

Если пакет уже импортирован обычным коммитом, T00 всё равно можно провести маленьким PR: проверить документы и отметить факт подготовки.

Для отдельной карточки используйте короткий запрос, заменив ID и заголовок
на нужные. Зависимости выбранной карточки должны быть закрыты в базовой ветке:

> Выполни только T02 из docs/TASKS.md. Прочитай AGENTS.md, ROADMAP.md и docs/STATE.md; проверь зависимости и критерии T02. Обнови roadmap в том же PR и docs/STATE.md. Подготовь PR «[T02] Движение Аладдина». Затем остановись, следующую карточку не начинай.

## Как идёт работа

Одна карточка, одна задача, один ограниченный PR. Пользователь ревьюит результат. Агент выполняет код/ассеты/проверки выбранной карточки и обновляет roadmap в том же diff.

После merge основная ветка получает код и галочку. Закрытый без merge PR прогресс не меняет. Незавершённая карточка остаётся пустой даже при полезном частичном коде.

Полный эпизод собирается за несколько задач. После T02 можно ревьюить движение, после T03 карту, после T09 бой, после T14 заказ. Сборку T20 можно получить до окончательной графической приёмки. Все технические ограничения сообщаются честно.

## Объём и лимит

Промпт ограничивает работу одной карточкой; техническое ограничение расхода подписки он не устанавливает. Размер карточек и реальный расход различаются. Не перечитывай весь проект, не переустанавливай окружение и не запускай параллельных агентов без необходимости. Если карточка велика, дели её; не поручай целую фазу.

Команды управления и проверки дополняются по мере реализации карточек. Ссылки на roadmap и короткий рабочий цикл сохраняются.
